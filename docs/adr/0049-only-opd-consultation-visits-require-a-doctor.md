# Only OPD Consultation Visits Require a Doctor

A Visit's Doctor is optional unless its VisitType is an OPD Consultation (VisitType code `OPD`). Follow-up, Procedure, Vaccination, Emergency and any other VisitType may be checked in — as a Walk-in Visit or from an Appointment with no Doctor — without naming one. `visit.doctor_id` is nullable and the API returns `doctor: null` for such a Visit. The same rule applies when a Completed Visit is amended (ADR 0047): clearing the Doctor is rejected only when the amended VisitType is an OPD Consultation.

Front-desk staff create many Visits that no Doctor sees — therapy sessions delivered by a Therapist, vaccinations, procedure follow-throughs — and forcing them to pick a Doctor for these recorded a false clinical relationship and skewed each Doctor's queue. A consultation is the encounter that is, by definition, with a Doctor, so it alone keeps the requirement.

The rule keys on the VisitType **code**, not its name, because the name is Tenant-editable display text. It lives in one pure helper (`visitTypeRequiresDoctor`) shared by the check-in and amend validators and by the Create Visit and Amend Visit forms, so the server and the UI cannot disagree.

**Queue Tokens.** ADR 0029 numbers tokens per Doctor per Tenant-local day. A Visit without a Doctor draws instead from the Tenant's shared **unassigned queue** for that day (`visit_unassigned_queue_token_counter`), which starts at `1` and follows every other ADR 0029 rule: check-in order, never rewound, never reused after cancellation. A partial unique index (`visit_unassigned_day_token_idx`) keeps those tokens unique, because Postgres treats NULL Doctor IDs as distinct in the per-Doctor index.

**Considered.** Giving Doctorless Visits no Queue Token was rejected: the arrival workflow still calls these Patients in order, and a nullable token would ripple through every queue display. A per-VisitType "requires Doctor" flag on the VisitType Master was deferred until a Tenant needs a second Doctor-only VisitType; until then a hard-coded `OPD` code keeps the rule visible and testable.

**Consequences.** Amending a Visit's Doctor keeps its Queue Token (ADR 0047), so moving a Visit between a Doctor and the unassigned queue on the same day can collide with a token already issued there. The unique indexes reject such a collision rather than duplicating a token, but the amend command does not yet map that rejection to a clean conflict — the same pre-existing gap as amending between two Doctors. Lists, the Visit header and the Patient timeline show "No Doctor" (or no Doctor name) for these Visits, and a Doctor filter does not match them.
