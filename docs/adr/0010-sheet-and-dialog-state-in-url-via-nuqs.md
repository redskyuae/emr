# Sheet and Dialog Open-State Lives in the URL via nuqs

Slide-over sheets and modal dialogs that represent a distinct sub-view — creating a Role, editing a Role — previously tracked their open-state in component `useState`. The Roles page had grown a hybrid of this and a half-measure URL integration: `page.tsx` read `?create=1` server-side, passed an `initialCreateOpen` prop, and the client component replayed it once through a `useRef` guard and a manual `router.replace` on close. The result was two mechanisms (URL for create, local state for edit), state that did not survive a refresh, and edit views that could not be deep-linked or shared. We are moving this open-state into the URL using `nuqs` (`useQueryState`), with `NuqsAdapter` mounted alongside the existing providers.

A single query param drives the entire surface rather than one boolean per action: for Roles, `?role=new` opens the sheet in create mode, `?role=42` opens it in edit mode for Role 42, and an absent param means closed. The container derives the mode from the param and resolves the target entity from already-loaded query data (showing the sheet's skeleton while that data loads, and clearing the param if the id resolves to nothing). `page.tsx` no longer reads `searchParams` for this; it renders a plain container. This makes every sub-view deep-linkable, refresh-stable, and back-button friendly, and gives future screens one rule to copy instead of inventing per-screen open-state.

The trade-off is that open-state now appears in the URL, so the param names become a small surface we must keep stable and tidy (avoiding leftover params on close, which `nuqs` handles by setting the value to `null`). For ephemeral, non-navigational UI — a dropdown, a tooltip, an inline toggle — local state remains correct; this convention applies specifically to sheets and dialogs that are conceptually their own view.

The decision is reversible at the component boundary but, like the form convention, reversing it means touching every adopted screen, so new screens should follow it. The mechanical rules live in the "Screen composition" section of `CLAUDE.md`, and this pattern pairs with the form convention in `docs/adr/0009-client-forms-use-react-hook-form.md`.
