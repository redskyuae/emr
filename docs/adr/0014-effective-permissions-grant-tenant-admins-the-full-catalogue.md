# Effective Permissions Grant Tenant Admins the Full Catalogue

A user's Effective Permissions (exposed by `/api/v1/me`) are the de-duplicated union of the Permission Assignments of every Role assigned to that user — except for a Tenant Owner or Tenant Admin, whose authority lives in BetterAuth organization membership (`member.role` of `owner`/`admin`) rather than in Role Assignments. Because Tenant Provisioning makes the founding user an organization `owner` without creating a Staff profile or any Role Assignment, computing Effective Permissions purely from Role Assignments would leave every Tenant's founding user with zero permissions.

We resolve this by short-circuiting: when membership is `owner` or `admin`, Effective Permissions are the entire active Permission Catalogue. We chose this over (a) assigning the founding user the `TENANT_ADMIN` Role at provisioning — which contradicts the domain rule that a Tenant Owner "is not itself a Role" and widens the provisioning change surface — and over (b) returning an empty set, which is simply wrong for UI gating. This mirrors the existing membership-based authority check in `requireTenantAdminSession` and the `TENANT_ADMIN_DEFAULT_PERMISSIONS = 'ALL'` seeding intent. The trade-off is that an Admin's Effective Permissions are not the literal sum of their Role Assignments, so the permission list is authoritative for what the UI may show but is not a record of which Roles granted access.
