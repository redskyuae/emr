# Backend Modules Ship With Colocated Tests

Every backend module under `app/api/lib/modules/` carries colocated Vitest tests, written in the **same change** as the code they cover — not as a follow-up. The required coverage is one test file per layer: a schema unit test, a validator unit test, a command unit test, a query unit test, and a repository integration test (route handlers are tested only when their adapter logic is non-trivial). A backend change is not done until the whole suite (`bun run test`) and the type-checker (`bunx tsc --noEmit`) are green.

The CQRS + Repository + Validation layering exists precisely so each concern can be verified in isolation: schemas and validators are pure or repository-backed and mock cleanly; commands and queries are exercised against mocked validators/repositories through their public interface; repositories are the only layer that needs a real database, and they get DB-backed integration tests for tenant isolation, soft-delete filtering, and DB-level uniqueness. Tests written this way pin the _actual_ implemented contract (for example, commands map known Postgres `23505` violations to a `CommandResult` conflict and re-throw unexpected errors) rather than an idealized one, so they stay honest and catch regressions during refactors.

Writing the tests alongside the code — rather than batching them later — is the decision because retrofitting an entire codebase's tests is expensive and error-prone, and untested layers rot silently. Two traps make "looks tested" diverge from "is tested," so they are called out explicitly: Vitest only discovers the exact suffixes `*.unit.tests.ts` and `*.integration.tests.ts` (plural — `*.unit.test.ts`, `*.test.ts`, and `*.spec.ts` are silently ignored and never run), and a test that passes at runtime can still fail `tsc`, so type-checking is part of "green."

**Scope:** all backend code under `app/api/lib/modules/**` and the schemas under `app/db/schema/**`. The binding policy lives in `CLAUDE.md` → _Backend testing policy_; the per-layer worked examples, mocking patterns, and module-shape reference table live in `docs/backend-testing.md`. This ADR records the decision; those documents are how to follow it.
