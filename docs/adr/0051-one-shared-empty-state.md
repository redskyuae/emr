# One Shared Empty State, With a Coloured Duotone Icon

Empty screens in the EMR were built screen by screen: about 30 were a bare "No …" sentence and 99 more composed the shadcn `Empty` primitives into a small blue icon tile. Several said "match the current filters" when no filter was set, so staff could not tell "nothing exists yet" from "my search was too narrow", and most offered no next step. The Whiteboard design (white-board-v3, its ADR 0054) had already solved the same problem with one component, and the EMR adopts that design.

**One component.** `EmptyState` in `components/app/empty-state.tsx`, beside `StatCard`, built on the `Empty` primitives in `components/ui/empty.tsx`, which stay unchanged. It takes `icon`, `title`, `description`, `actions`, `children`, `tone`, `size` and `orbit`. Screens no longer compose the `Empty` primitives themselves, and no longer write bare "No …" sentences for an empty page, tab, list, table or card body.

**How it is drawn.** A bare centre icon (no tile behind it): 48px for a page or tab (`lg`), 40px for the body of a main card (`md`), 32px for sheets, dialogs, side panes, dashboard widgets and cards that sit beside several others (`sm`). The size follows the role of the space, not what wraps it, so a table inside a card that stands in for the tab is `lg`. At `md` and `lg` the icon sits in an SVG orbit of four rings and seven small tiles in a 320 × 200 box, each tile placed by ring and angle so it is centred on the ring's line; an elliptical mask fades the orbit at the edges, so no ring is cut off at any width, and the title overlaps the faded lower part. `sm` has no orbit, and `orbit={false}` removes it at any size. The orbit and icon are `aria-hidden` and are not printed. Nothing moves.

**Icons: Phosphor duotone from the installed `react-icons`.** `react-icons/pi` already ships Phosphor's duotone weight (`Pi…Duotone`), which draws its back layer at 20% opacity of `currentColor`, so one text colour gives both tones. Whiteboard added `@phosphor-icons/react` only because it was on Lucide; the EMR adds no icon package. `icon` is typed `IconType`, so a light-weight icon compiles but draws one tone: review catches it. Duotone is allowed for the `EmptyState` centre icon only; Circum and Phosphor Light remain the icon set everywhere else. `react-icons` renders in Server Components, so the component needs no client boundary.

**Colour by subject, from tokens.** Only the centre icon takes colour, and the same subject has the same colour on every screen (the table lives in `DESIGN.md`). Whiteboard used raw palette classes (`text-teal-600`); the EMR uses tokens. Existing tokens carry the hues they already have: `primary` for blue, `procedure` for violet, `chart-4` for teal, `success` for green, `destructive` for danger and `muted-foreground` for neutral. Sky, orange and amber are new `--tone-*` tokens with light and dark values, used only here. Amber is its own token rather than `--warning`, so a Masters list does not read as a warning. The identity accents (`gender-*`, `phone`) are not reused. `tone` has no default, so each screen chooses its subject.

**Nothing yet vs no match.** A screen that showed one message for both cases now shows two: the subject's icon and colour with the page's existing main action (when the user has permission for it), or "No results found" in neutral with a magnifying glass and no create button. An empty state has at most one primary action, and only one the page already offers; repeating the page's create action inside its empty state is not a duplicate of the header's action.

**What stays as it is.** A line under a form field or inside a picker's result list, "none" and placeholder options, a dash in a single field or cell, captions on stat cards, checklists and charts, the "None recorded." lines in the Visit side pane and Diagnoses, warning and save-failed alerts, and the plain lines on printed documents. Load errors stay red alert banners with their retry; only full-page "no permission" and "not found" panels move to `EmptyState`, with the `danger` tone and no orbit.

**Considered.** Restyling the `Empty` primitives in place was rejected: `components/ui/` is themed shadcn and is not forked, and composition by every screen is the inconsistency being fixed. Adding `@phosphor-icons/react` was rejected as a second copy of an icon set `react-icons` already ships. Colouring by meaning only (brand, success, warning) was rejected because most empty states have no status, and the subject colour is what lets staff recognise a screen's empty state at a glance.
