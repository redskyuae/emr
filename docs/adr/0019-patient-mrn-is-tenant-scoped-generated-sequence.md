# Patient MRN Is a Tenant-Scoped, System-Generated Sequence

A Patient is identified for humans by a Medical Record Number (MRN), as recorded in `CONTEXT.md` — the identifier quoted at the front desk, printed on wristbands, labels, and reports. We decided the MRN is **assigned by the server when the Patient record is first created**, including creation as a Provisional Patient, and is a **monotonic sequence scoped to the Tenant** rendered as `MRN-` followed by a zero-padded (minimum four digit) integer (e.g. `MRN-1001`, `MRN-1042`). Clients never send the MRN on create; the server allocates the next value for that Tenant and returns it. The MRN remains immutable as Patient Registration is completed, and the integer identity column remains the true primary key.

The MRN is scoped to the **Tenant, not the Facility**. A hospital group wants one record — and one MRN — per person across all of its Facilities; per-facility MRNs are the classic source of duplicate patient records that later require merging. (There is also currently no Facility table to scope against; Asset location relations are free text per ADR 0008.) Staff-entered MRNs were rejected for day-to-day use because they invite typos and collisions; if a future data-migration task needs to import legacy MRNs, that will be a deliberate, separate import path rather than an open write surface on registration.

Generation reuses the counter pattern from ADR 0011 (Work Order codes): a dedicated `patient_mrn_counter` row keyed by Tenant, atomically inserted or incremented with `RETURNING` inside the same transaction as the Patient insert, first allocation 1001. Gaps are acceptable; strict contiguity is not a requirement. Soft-deleted Patients retain their MRNs and their numbers are never reused, so per-Tenant uniqueness is backed by a **full** unique index on `(tenant_id, lower(mrn))` that includes soft-deleted rows — a reset, allocation bug, or non-application write cannot duplicate a historical medical identifier.

This decision is effectively irreversible once Tenants register real Patients: MRNs will exist on printed material and in records outside the system, so changing the format or scoping later would invalidate identifiers in operational use.
