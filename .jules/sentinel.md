## 2025-02-14 - [CRITICAL] IDOR via Unauthenticated Tenant ID in Query Params/Payload

**Vulnerability:** The codebase contained an IDOR (Insecure Direct Object Reference) vulnerability pattern where endpoints (e.g., `app/api/v1/appointments/types/route.ts`) were trusting the `tenantId` extracted from query parameters (`getTenantId(request)` which read `request.nextUrl.searchParams.get('tenantId')`) or request payloads, without properly verifying it against an authenticated session. This allowed unauthenticated users or malicious actors to bypass tenant boundaries and access/modify resources belonging to other tenants.
**Learning:** Hardcoding a `getTenantId` extraction from query parameters as a temporary workaround (e.g., `TODO: extract tenantId from BetterAuth session once auth is implemented.`) creates severe systemic vulnerabilities. If endpoints rely on client-provided boundaries, they bypass isolation entirely.
**Prevention:** Always use the verified active session to determine boundary scopes. In this Next.js app, replace insecure extraction with `const tenantSession = await requireTenantSession();` (or `requireTenantAdminSession()`) from `auth-helpers.ts`. For `GET` and `DELETE`, pass `tenantSession.tenantId` into queries/commands. For mutations (`POST`/`PUT`), intercept the payload and forcefully assign the `tenantId` (e.g. `payload.tenantId = tenantSession.tenantId`) to ensure data cannot be created or updated outside the user's verified tenant scope.
